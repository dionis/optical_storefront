2 · Identidad visual (Óptica El Rancho / RUBI_LENS)

La marca se tomó de opticaelrancho.com. El logo RUBI_LENS (montura con lente izquierdo azul y derecho rojo) se re-dibujó como vector SVG en public/logo.svg — trazos de montura + texto en vez de un recorte PNG, por lo que se ve nítido a cualquier tamaño y sin bordes sucios. La paleta se extrajo analizando los píxeles del logo con Pillow:

  • Azul primario #0E5AD0 — barra superior, botones primarios, enlaces activos, selección.
  • Rojo "rubí" #FD0E3F — precios, badges del carrito, acentos.
  • Texto #16181d, footer azul marino #0e1830.

El favicon es un SVG vectorial de dos lentes (azul + rojo) que replica el icono del logo; theme-color = azul de marca.

3 · Cómo se renderiza (arquitectura)

Es una SPA (Single Page Application) React 18 servida por Vite. Al arrancar muestra los datos «semilla» incluidos en el build y luego hidrata el catálogo desde catalog.json/cases.json (generados por el servicio diario, ver más abajo). Enrutado en cliente con react-router-dom.

RutaComponenteQué renderiza
/HomeHero, grid de 17 marcas (grande, con nombre), 8 destacados, franja de propuestas de valor
/catalogo, /marca/:slugCatalogSidebar de filtros (colapsable en móvil), orden, búsqueda; grid de ProductCard
/producto/:slugProductDetailGalería con cambio de imagen por color, specs, CTAs
/recetas/:slugLensProcessAsistente de 4 pasos con precio dinámico
/estuches, /marca/caseCatalog (rama case)Cuadrícula de estuches, con variantes de color una a una como los espejuelos

El header incluye dos cajones deslizantes globales: Favoritos (icono ♥) y Carrito (icono 🛒), cada uno con su contador. Favoritos y carrito se guardan en localStorage (oer_fav, oer_cart) y persisten entre recargas; desde Favoritos se puede «Añadir al carrito» o «Quitar».

Catálogo dinámico — servicio en la nube (ya no es estático)

El catálogo ya no está fijo en el código: se regenera solo cada día mediante un servicio preparado para la nube (pensado para el modelo SaaS, sin depender de ninguna PC). El servicio es scripts/sync-catalog.mjs — Node puro, sin dependencias, configurable por variables de entorno — y hace lo siguiente:

  • Consulta la WooCommerce Store API pública de la tienda origen (/wp-json/wc/store/v1/products, ~6 peticiones para todo el catálogo). La tienda origen es configurable (CATALOG_SOURCE) para servir a varios tenants SaaS.
  • Se queda solo con los marcos disponibles (is_in_stock === true): si un modelo deja de estar disponible desaparece automáticamente de la tienda.
  • Detecta modelos nuevos de cualquier marca (la marca sale de la categoría del producto) y los agrega automáticamente — incluso marcas que no existían antes.
  • Normaliza los atributos al español canónico (Square→Cuadrado…) y agrupa los tamaños a los rangos de los filtros; reutiliza las imágenes por color ya conocidas y solo descarga la galería de los modelos nuevos.
  • Escribe catalog.json, cases.json y catalog-meta.json (fecha de sincronización, conteos por marca y el diff added/removed de ese día) en el directorio configurable CATALOG_OUT_DIR. Si la API falla, no sobrescribe el último catálogo bueno.

Despliegue en la nube (3 caminos, documentados en scripts/README.md):

  • GitHub Actions (incluido): .github/workflows/catalog-sync.yml corre a diario (08:00 UTC) en la infraestructura de GitHub y commitea el catálogo regenerado. Cero infraestructura propia.
  • Contenedor Docker (incluido): scripts/Dockerfile es un job de una sola ejecución para Cloud Run Jobs, ECS Scheduled Tasks, Kubernetes CronJob, Azure Container Apps, etc.
  • Cualquier cron serverless (Vercel/Cloudflare/Lambda): invocar el script y publicar los JSON en un CDN/bucket.

La tienda (SPA) lee esos JSON en tiempo de ejecución vía src/data/catalogStore.js (useCatalog()): al abrir, muestra al instante los datos «semilla» incluidos en el build y, en cuanto llega el catalog.json, re-renderiza con lo disponible. La URL del catálogo es configurable con VITE_CATALOG_URL — para SaaS se apunta al catálogo hospedado en la nube (CDN), desacoplado de cualquier máquina. Si no hay red, se queda con la semilla. Así el catálogo se refresca sin recompilar ni reiniciar.

Render de imágenes y colores

Las imágenes de producto se enlazan directamente (hotlink) desde el CDN de caprioptics.com con la URL exacta por color. Al pasar el cursor o hacer clic en una muestra de color, el estado React active cambia y se re-renderiza <img src={color.image}> con una transición fade-in — replicando el comportamiento de dc406. Las muestras de color se pintan con un mapa nombre→hex.

Datos

  • 17 marcas reales con logos oficiales (src/data/brands.js).
  • ~550 monturas disponibles de todas las marcas de caprioptics — el número exacto cambia cada día según lo que la API reporte disponible. La semilla incluida es el catálogo COMPLETO capturado: Di Caprio (129), 4U (134), Peachtree (54), Millennial (45), Simplylite (29), Flexure (25), Trendy (21), Ago (19), Grande (15), Versailles Palace (15), Eyeleos (13), Artistik Eyewear (13), ProRx (9), Candy Shoppe, Artistik Galerie, Slimfold. Los atributos se normalizan al español canónico (Square→Cuadrado, Acetate→Acetato…) y los tamaños se agrupan en los rangos exactos de los filtros, para que filtros y traducción funcionen.
  • 28 estuches / cases reales (src/data/cases.js) — categoría Case completa — con imagen y precio, vendibles; los que tienen varios colores muestran cada variante una a una.
  • Precio y valoración deterministas por SKU (Capri Optics es B2B y no publica precios).

Estuches (cases) y venta cruzada

  • La marca Cases (/marca/case) y el enlace «Estuches» del menú muestran una cuadrícula de estuches con botón «+ Añadir» que los agrega al carrito.
  • Los estuches siguen la misma dinámica que los espejuelos: cada tarjeta es clicable y abre su propia ficha /estuche/:slug (CaseDetail.jsx) con imagen grande, cambio de color una a una, botón de favoritos ♥, añadir al carrito, ficha de especificaciones, bloque de reseñas y recomendación de «otros estuches». La tarjeta también tiene su propio corazón de favoritos.
  • En cada ficha de espejuelos se muestran 3 estuches recomendados («Completa tu compra con un estuche»), elegidos de forma determinista a partir del SKU, cada uno con su botón de compra — cross-sell para aumentar el ticket.

Configurador de lentes / receta (estilo Zeelool)

  • Flujo de 4 pasos reordenado: Uso → Receta → Lente → Resumen.
  • La receta usa listas desplegables en todos los campos con valor por defecto 0.00: ESF/SPH (−20.00 a +12.00), CIL/CYL (−6.00 a +6.00), EJE/AXIS (1–180°), DP/PD (50–76) y ADD (+0.75 a +3.50, solo en progresivos), en pasos de 0.25.
  • Cálculo acorde a la graduación: se toma el valor absoluto más alto de esfera/cilindro (y si es infantil, policarbonato) y se recomienda automáticamente el índice de lente más adecuado (1.50 → ±2, 1.61 → ±4, 1.67 → ±6, 1.74 → >±6), destacándolo con una insignia.
  • 5 materiales seleccionables (1.50 CR-39, 1.59 policarbonato, 1.61, 1.67, 1.74): cada uno es una casilla elegible con un globo de ayuda ⓘ que, al hacer clic, explica cuándo conviene o no ese material (se quitó el prefijo «buena práctica»).
  • Tratamientos (antirreflejo, filtro de luz azul, fotocromático, tinte de sol) como casillas marcables, cada una con su globo de ayuda ⓘ explicando cuándo es prudente.

Reseñas por producto

  • Cada ficha de espejuelos incluye un bloque «Escribe una reseña»: valoración por estrellas (1–5), nombre y comentario.
  • Las reseñas se guardan en localStorage (oer_rev_<slug>) por producto y se listan al instante; la media mostrada combina la valoración base del SKU con las reseñas nuevas.

Refinamiento visual

  • Sin diferencia de fondo: las tarjetas usan exactamente el mismo fondo blanco que la página (borde transparente en reposo), de modo que la imagen del producto no queda «recortada» sobre un rectángulo gris.
  • Énfasis por movimiento: al pasar el cursor la tarjeta se eleva y la montura se agranda/rota levemente, con sombra suave y un borde tenue — todo sobre blanco.
  • En el header se muestra solo el logo RUBI_LENS (sin el texto «Óptica El Rancho»).
  • El panel lateral de filtros ahora tiene scroll propio (max-height + overflow-y:auto): cuando todos los filtros están desplegados se puede bajar por ellos sin quedar bloqueado.
  • Todos los grupos de filtros inician cerrados al cargar el catálogo (menos ruido visual; el usuario abre solo lo que necesita).
  • Scroll al inicio automático: al navegar a cualquier página (montura, marca, estuche, receta…) la vista salta arriba (componente ScrollToTop sobre el cambio de ruta), y al aplicar un filtro, orden o búsqueda el listado también vuelve al inicio — ya no te deja «tirado» al final de la página.

4 · Bilingüe (ES / EN)

Sistema de i18n propio y ligero, sin dependencias:

  • src/i18n/translations.js — diccionario T con todas las cadenas de UI en es y en (nav, botones, hero, filtros, flujo de recetas, footer…), y un mapa VAL que traduce los valores de atributos (p. ej. «Cuadrado»→«Square», «Acetato»→«Acetate»).
  • src/i18n/LanguageContext.jsx — contexto React que expone t(clave) y tv(valor). El idioma se detecta del navegador, se conmuta con dos banderitas en el header (🇪🇸 Español y 🇺🇸 English, SVG en línea; la activa se resalta con un anillo azul) y se persiste en localStorage; también actualiza <html lang>.
  • Todo texto visible pasa por t()/tv(): cambiar de idioma re-renderiza la web entera al instante.

Arquitectura (sin tocar el backend de Dionis)

  • Auth (src/admin/adminAuth.js): gate en cliente, contraseña como hash SHA-256 (nunca en texto plano), sesión de 8 h en sessionStorage. No es una barrera de seguridad real (todo corre en el navegador): para producción/SaaS se conecta a un backend de auth real vía VITE_ADMIN_AUTH_URL (único seam).
  • Analítica (src/admin/analytics.js): registra eventos reales de uso (accesos, vistas, añadir-al-carrito, favoritos) y órdenes al hacer checkout, en localStorage; el checkout de la tienda ahora crea una orden real. Incluye datos demo sembrados (etiquetados, con botón «Borrar demo») para que las gráficas no salgan vacías. Para métricas reales multi-dispositivo, enviar al backend (seam en el mismo archivo).
  • Precios (src/admin/priceStore.js): overrides por SKU/clave persistidos en localStorage + export/import JSON; el catálogo se re-renderiza al instante al cambiar un precio (el catalogStore se re-enriquece). Base para SaaS: persistir vía backend (seam).
  • Gráficas (src/admin/charts.jsx): SVG propias, responsivas y accesibles, sin dependencias.
  • Ruta /admin con layout propio (sin header/footer de tienda); enlace discreto en el pie.

Acceso (modo demo): el login del panel acepta cualquier correo + contraseña (el correo se muestra en la barra del panel). La tienda tiene además un botón 👤 «Acceso» en el encabezado para que los clientes inicien sesión / creen cuenta (src/components/userAuth.js).

Preparado para 2FA: el auth del panel ya tiene el segundo factor listo (paso de código en el login). Se activa con VITE_ADMIN_2FA="true" — en demo acepta cualquier código de 4–8 dígitos; para TOTP/SMS real se apunta VITE_ADMIN_2FA_URL al backend de Dionis. Ver src/admin/adminAuth.js (verifyOtp) y GUIA-PANEL.md.
